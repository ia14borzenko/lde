# Обращения агентов о работе в LDE

Сюда агенты, работающие в LDE (DSH и др.), пишут обращения: ошибки LDE, недостающие инструменты,
ручную рутину, непонятные места скилла и документации. Владелец читает их (`lde feedback list`,
Studio → меню проекта → «Обращения агентов») и передаёт в разработку LDE. Отчёт самодостаточен:
читающий не видит сессию агента.

Отчёты (`reports/*.md`) в git не попадают: в них бывают фрагменты проектов пользователей.

## Как пишет агент

1. **Сначала сверка** — может, нужное в LDE уже есть:
   `lde feedback check "что нужно сделать"` → подходящие команды или «известный пробел».
2. **Обращение**, если: LDE ошиблась; нужного инструмента нет; пришлось вручную делать то, что
   просится в одну команду (массовые однотипные правки, десятки одинаковых вызовов); скилл или
   справка не объяснили, как сделать.

       lde feedback new --kind missing --title "Нет переименования величины по всему документу" \
           --asked "Пользователь: «замени R_ц на R_t везде»" \
           --did "lde list quantities, правка quantities.toml" \
           --manual "Заменил {R_ц} → {R_t} вручную в 14 местах 4 файлов" \
           --want "lde rename quantity R_ц R_t" --severity medium

   Виды: `bug` — ошибка LDE, `missing` — нет инструмента, `routine` — много ручной рутины,
   `docs` — непонятно из скилла/документации, `ux` — неудобно. Серьёзность: `low|medium|high|blocker`.
   Длинное описание — `--file подробно.md`.
3. **В конце длинной задачи** — `lde feedback analyze`: LDE сама ищет рутину по журналу команд
   проекта (`.lde/journal.jsonl`) и истории правок.

LDE дописывает к обращению сама: версию, проект, сводку `lde check`, сверку с возможностями LDE,
признаки рутины и последние команды агента. Повтор той же проблемы (тот же вид и заголовок)
дописывается в существующий файл со счётчиком «Повторов».

## Правила

- Один файл — одна проблема. Заголовок — что не так, одной фразой.
- Что просил пользователь — его словами (цитатой); не выдумывать.
- Никаких секретов (пароли, ключи, токены, ссылки на документы с ключом после `#`).
- Фрагменты текста проекта — только необходимые для понимания.
- Сообщить пользователю в ответе, что обращение записано (путь к файлу).

## Статусы (меняет владелец)

`open` → `forwarded` / `fixed` / `duplicate` / `wontfix`: `lde feedback status <id> <статус>`.
