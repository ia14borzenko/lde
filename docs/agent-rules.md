# Правила для агента (LDE v2)

Короткая версия — в скилле `skill/lde/SKILL.md` (его читает DSH и любой агент). Здесь — почему так.

## Можно

- Писать и дописывать текст в `text/*.md`; добавлять величины, сокращения, источники, расчёты
  через `lde new …` или правкой `quantities.toml`, `abbreviations.toml`, `refs.bib`, `calc/*`.
- Запускать `lde check`, `lde fix`, `lde update`, `lde build`, `lde docx`, `lde submit`, `lde save`.

## Нельзя

| Запрет | Почему |
|---|---|
| набирать обозначения величин текстом или формулой (`Rц`, `$R_{ц}$`) | провал №6 RDE: агент так и делал; линтер ловит `qty-as-text`/`qty-as-math` — ошибка |
| писать номера рисунков, таблиц, формул, источников цифрами | номера считает LDE; ручной номер расходится при перенумерации (провал №7 RDE) |
| вставлять LaTeX-команды в текст, `\label`/`\tag` в формулы | вёрстку делает LDE; одинаковые номера PDF/DOCX гарантирует один код |
| править `out/`, `.lde/`, `calc/*/out/`, `import/` | производное или архив импорта: восстанавливается командой |
| менять чужой текст «заодно», переформатировать файлы | автор видит «Что изменилось» по элементам; лишние правки — шум и риск |
| запускать `git reset/checkout/clean` в проекте | история — журнал точек сохранения автора; откат — `lde undo` |

## Как проверять работу

1. `lde check` → «Замечаний нет» (ошибки — обязательно; замечания — по смыслу).
2. `lde status` → «Всё актуально» (иначе `lde update`).
3. `lde build` → PDF собран; при ошибке LaTeX сообщение указывает файл и строку.
4. `lde save -m "что сделано"` — автор увидит это в Studio («Что изменилось»).

Проверено на реальном агенте (DSH, сценарии с правкой настоящего отчёта).

## Обращения агента (lde feedback)

Если LDE ошибается, нужного инструмента нет, приходится делать рутину вручную или скилл не объясняет,
как сделать, — агент сначала сверяется (`lde feedback check "…"`), затем пишет обращение
(`lde feedback new --kind bug|missing|routine|docs|ux …`). Ящик — `agent-feedback/` рядом с LDE
(правила — `agent-feedback/README.md`); LDE сама дописывает версию, проект, сводку проверки, сверку с
возможностями и признаки рутины по журналу команд проекта (`.lde/journal.jsonl`, `lde feedback analyze`).
Владелец читает обращения в Studio (меню проекта → «Обращения агентов») или `lde feedback list`.

## Подключение по MCP (lde mcp, Р35)

Если агент подключён к MCP-серверу LDE, те же правила действуют через инструменты: `project_status`
→ `lde_guide` → `outline`/`element` → `edit_element` (передавай `base_src` — исходник, который видел;
если автор успел поправить элемент, правка отклоняется, а не затирает его) → `check` → `build` →
`render_page` (посмотреть страницу) → `version_create` для этапа. Ответ `edit_element`/`insert_element`
уже содержит проверку места — исправь замечания сразу. Каждая правка — точка «Агент …» в истории,
автор видит её в Studio и может отменить. Правки рецензентов (`share_*`) — только по просьбе автора.
